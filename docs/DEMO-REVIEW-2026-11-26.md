# 합성 데이터 기반 로그인·업무 흐름 점검 (2026-11-26 KST)

## 검증 환경

- FE `http://127.0.0.1:5175` → 실제 Spring API `http://127.0.0.1:8081`, 격리된 MySQL `toki_demo`.
- `/demo` 프런트엔드 시뮬레이터가 아닌 일반 로그인 화면에서 팀원·팀장 계정으로 각각 로그인했다.
- 외부 Gemini 응답만 demo 프로필의 고정 응답으로 대체한다. 아래 수치는 실제 업무 성과나 공급자 청구 내역이 아니다.
- 기존 팀 2에서 브라우저 시현 후, API 시드를 다시 실행해 새 팀 3을 생성하고 재검증했다. 기존 팀은 삭제하지 않았다.

## 확인 결과

| 점검 항목 | 관찰·검증 결과 |
| --- | --- |
| 팀원 실제 로그인 | 팀 선택 후 팀원 메뉴로 진입, 개인 분석 이력 4건 확인 |
| 확인값 저장 | 피드백 상세에서 성공 확인과 오류 수정 이유를 저장, 완료 안내 확인 |
| 근거 원문 | 본인의 사용자·AI 메시지와 피드백 근거 강조 표시 확인 |
| 팀장 실제 로그인 | 팀 제출 6/6명, 분석 24/24건, 목표 수정·팀 설정 메뉴 확인 |
| 공유 가이드 | 팀원 가이드 열람, 팀장 공유 사례 가이드 지정 저장 및 버튼 상태 변경 확인 |
| 파일 내 중복 | 계정마다 입력 5행 → 고유 후보 4건 → 분석 4건, 6명 합계 24건 |
| 충돌 ID·재업로드 | 같은 ID·다른 내용은 CONFLICTING_CONVERSATION_ID, 동일 내용 재업로드는 선택 불가 |
| 성과 집계 | 성공 18/24 = 75%, 오류 수정 6/24 = 25% |
| 토큰 집계 | 24개 고유 대화의 개인 일자 상세 토큰 합 = 팀 지표 분자 984토큰, 성공당 984/18 = 54.67 (화면 54.7) |
| 개인 표본 정책 | 4건 < 최소 표본 20건이므로 개인 성공률은 null·INSUFFICIENT_SAMPLE. 화면도 표본 부족 표시 |
| 권한 분리 | 팀원도 TEAM KPI 조회 가능, 팀장의 팀원 개인 피드백·분석 조회는 404, 팀원의 설정 변경은 403 ROLE_FORBIDDEN |
| AI 판정과 본인 확인 분리 | 합성 AI 결과는 UNKNOWN이며, 시드가 기록한 본인 확인 결과로 성과 계산 |

시드를 다시 실행한 뒤 `node scripts/verify-local-demo.mjs`로 위 집계·권한을 검증했다. 파일 중복·업로드 회귀 테스트 `InFileDuplicateTest`, `UploadFlowTest` 17건도 통과했다. 이 기록은 전체 테스트를 새로 실행했다는 의미는 아니다.

## 로직이 드러나는 부분

업로드 → 중복 제거 → 분석 → 본인 결과·재작업 확인 → 개인/팀 성과 → 공유 승인 → 팀장 가이드 지정 → 팀원 재활용 흐름은 확인 가능하다. 분석 처리 성공과 실제 업무 성공을 별도 상태로 다루고, 팀장에게도 개인 원문을 노출하지 않는 점이 화면과 API에서 일치한다.

| 우선순위 | 보완할 점 | 이유·완료 기준 |

| P1 | 개인별 최소 20건 이상인 별도 정상 시현 시나리오 | 현재 개인 성과는 전부 표본 부족이다. 기존 4건 시나리오는 정책 검증용으로 유지하고, 충분한 개인 표본에서 값이 표시되는 시나리오를 추가한다. |
| P1 | 온보딩 전후·복수 주간 데이터 | 현재 모든 대화가 11월 18일 하루에 있어 추이는 한 점이고 전후 효과를 판단할 수 없다. 기준 버전·토큰 출처를 맞춘 전후 표본을 만들고 기대 집계값을 검증한다. |
| P1 | 업무에 맞는 개선 후 예시 | 고객 예약 안내 업무인데 현재 고정 개선 예시는 정보 추출 템플릿이다. 모델 절약·맥락 보완·긴 대화 유형별로 같은 업무에 적용 가능한 예시를 제공한다. 실제 모델 품질은 별도 평가한다. |
| P1 | 비용 검증용 고정 단가·환율 시나리오 | 기본 환율은 0이고 가격 계산은 환율이 양수일 때만 값이 생긴다. 현재 984토큰 검증을 실제 비용 검증으로 표현하면 안 된다. 테스트 전용 고정 환율·단가로 중복 제거 전후 예상 비용을 비교하며, 실제 청구 금액과 구분한다. |
| P2 | 현실적인 입력 다양화 | 현재 같은 짧은 업무와 고비용 모델이 반복된다. 실제 추가 요청이 있는 오류 수정/요구 변경/표현 개선, 긴 대화, 첨부 제외, 실패·미확인·부분 성공을 각각 구성한다. |
| P2 | 중복 처리 건수 안내 | API 원본 5행과 고유 후보 4건의 차이를 화면에서 ‘동일 ID 중복 1건 제외’로 설명하면 사용자가 집계 기준을 확인하기 쉽다. 기간 제외와 기존 업로드 중복도 구분해야 한다. |
| P2 | 공유 가이드 후 새 업무 비교 | 기존 가이드 조회·지정은 검증했지만 적용 후 새 대화의 개선 효과는 아직 검증하지 않았다. 적용 전후 데이터와 근거를 연결한다. |

운영 서버 로그인·배포 상태, 실제 외부 모델 품질, 실제 공급자 요금 청구는 이번 검증 범위에 포함되지 않는다. 소스 푸시는 운영 배포 완료를 의미하지 않는다.
